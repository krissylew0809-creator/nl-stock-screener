# AI 使用与验证记录

## 使用的 AI 工具
- Claude Code（Claude Sonnet 5.5）：需求拆解、架构、全部代码与测试的初稿、文档。
- 运行时 LLM（可选）：仅用于意图解析，默认关闭。

## AI 参与环节
需求分析 → 职责边界设计 → 后端（解析/引擎/数据层/服务）→ 前端 → 测试 → 文档。

## 过程中发现并修正的问题（可追溯）
1. 环境无 Node，已写好的 JS 后端无法验证 → 改为 Python 标准库实现，并真实运行测试与页面。
2. 扶摇文档页只给概览 → 逐个读取 financials/prices/valuations 子页，按其字段与单位实现（金额为元→换算亿元；`null` 不补零；同比用同报告期）。
3. 同比分母≤0 会得到无意义甚至误导的数值 → 改为记为“缺失”并写明原因（有测试）。
4. 初版测试里有一条自己写得过度复杂的断言 → 简化为 `selected+excluded+undetermined==total`。
5. 示例数据模式：避免“看起来像真实数据”的风险 → 顶部横幅、每条数据的 `src` 均标注“示例数据（合成，非真实）”，回看/监控同样提示。

## 真实数据核对（2026-10-21）
方法：对 5 只股票（贵州茅台、中国平安、宁德时代、招商银行、美的集团）直接调用扶摇原始接口，按 README 中的口径独立重算 8 个指标（共 40 个值），与线上网站（https://nl-stock-screener.onrender.com）返回值对比，容差为 0.3% 或 0.02。
结果：**40/40 一致**。网站对数值做了四舍五入（同比、比率保留 2 位，现金流保留 3 位亿元），差异均在舍入范围内。
附带观察（未修改，已作为已知边界）：
- 不同股票的“最新报告期”不同（如宁德时代为 2026Q3，其余为 2026Q2），页面逐条标注了时点，但跨股票比较时需留意。
- 银行/保险的“负债/总资产”普遍在 90% 左右，这是行业特性，不适合与非金融股用同一阈值比较。
- 隆基绿能去年同期归母净利润为负，同比被记为“数据缺失”而非硬算。
